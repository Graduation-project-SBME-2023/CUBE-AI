# 🗄️ Database Documentation

CUBE.AI uses **PostgreSQL 15** as its primary database, managed via **SQLAlchemy** ORM and **Alembic** for schema migrations.

---

## Connection Details

| Setting | Value |
|---|---|
| Host | `postgres` (Docker) / `localhost` (local dev) |
| Port | `5432` |
| Database | `workflow_db` |
| User | `workflow_user` |
| Password | Defined in `Backend/.env` |

**Connection string:**
```
postgresql+asyncpg://workflow_user:<password>@postgres:5432/workflow_db
```

## Schema Overview

The database contains the following core tables:

### `list_workflow` — Workflow Registry

Stores named annotation workflows.

```sql
CREATE TABLE IF NOT EXISTS list_workflow (
    task_name TEXT PRIMARY KEY
);

-- Enforce uniqueness
ALTER TABLE list_workflow ADD CONSTRAINT unique_task_name UNIQUE (task_name);
```

**Constraints:**
- `task_name` must be unique
- Deleting a workflow cascades and removes all records in `workflow` with that `task_name`

---

### `workflow` — Study-Workflow Assignments

Maps DICOM studies to annotation workflows.

```sql
CREATE TABLE IF NOT EXISTS workflow (
    case_id               TEXT,
    task_name             TEXT,
    series_instance_uid   TEXT,
    instance_uid          TEXT,
    annotated             BOOLEAN DEFAULT FALSE,
    train                 BOOLEAN,
    modality              TEXT,
    CONSTRAINT fk_task_name FOREIGN KEY (task_name)
        REFERENCES list_workflow(task_name)
        ON DELETE CASCADE
);
```

**Constraints:**
1. Each `instance_uid` must be unique
2. The same `series_instance_uid` cannot appear twice with the same `task_name`
3. `case_id` may repeat (multiple series per case)
4. `annotated` is set to `TRUE` when `instance_uid` is populated

---

### Research Session Tables

Managed by Alembic migrations. Include:

- **`research_sessions`** — Active/historical research sessions
- **`session_studies`** — Studies associated with a session
- **`agent_outputs`** — Cached agent outputs per session

## Alembic Migrations

Schema changes are managed via Alembic.

### Running Migrations

```bash
# From the Backend directory
cd Backend

# Apply all pending migrations
alembic upgrade head

# Check current migration state
alembic current

# Show migration history
alembic history
```

### Creating a New Migration

```bash
# Auto-generate from model changes
alembic revision --autogenerate -m "add_new_field"

# Create an empty migration
alembic revision -m "manual_migration"
```

### Migration Files

Located in `Backend/migrations/versions/`.

> ⚠️ Always verify autogenerated migrations before applying — Alembic may generate `DROP TABLE` statements if model imports are incorrect in `env.py`.

## Common Queries

```sql
-- View all workflows
SELECT * FROM list_workflow;

-- View all studies in a workflow
SELECT * FROM workflow WHERE task_name = 'MyWorkflow';

-- Check annotation status for a workflow
SELECT case_id, annotated FROM workflow WHERE task_name = 'MyWorkflow';

-- Delete all rows from workflow table
DELETE FROM workflow;

-- Filter unannotated cases
SELECT case_id FROM workflow WHERE task_name = 'MyWorkflow' AND annotated = FALSE;
```

## API Endpoints (Workflow Data)

The MONAI Label server exposes REST endpoints for workflow data management:

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/workflow/add` | Add a study to a workflow |
| `POST` | `/workflow/update-uids` | Update series/instance UIDs |
| `POST` | `/workflow/delete-multiple` | Delete multiple workflow records |
| `POST` | `/workflow/filter` | Get case IDs for a workflow |
| `POST` | `/workflow/filter-annotated` | Get annotation status per case |
| `POST` | `/workflow/filter-workflow` | Get full workflow data |
| `POST` | `/workflow/list_workflow/add` | Create a new named workflow |
| `GET` | `/workflow/list_workflow` | List all workflows |
| `DELETE` | `/workflow/list_workflow/delete` | Delete a workflow |
| `POST` | `/workflow/update-train` | Update train flag for a study |
| `GET` | `/workflow/get-train` | Get train flag for a study |

## pgAdmin Access

To browse the database visually:

1. Install [pgAdmin](https://www.pgadmin.org/)
2. Connect with the credentials from `Backend/.env`
3. Navigate to: `Servers → PostgreSQL → workflow_db → Schemas → public → Tables`

## Backup & Restore

```bash
# Backup
docker exec -t postgres pg_dump -U workflow_user workflow_db > backup.sql

# Restore
docker exec -i postgres psql -U workflow_user workflow_db < backup.sql
```
