System Architecture

A modular, AI-driven research workspace. Invoke specialized agent swarms on-demand to execute discrete tasks, or chain them seamlessly for full end-to-end scientific discovery.

1. Architecture Overview

RROS acts as a highly specialized collaborative copilot. The Manager Agent receives user instructions via the UI, plans a Directed Acyclic Graph (DAG) of sub-tasks, and delegates work across an event-driven Agent Mesh.

2. In Practice: Full Pipeline Use Case

Let's follow a real-world scenario to see how Tasks, Context, and Agents interact. The Request: "Design and execute a study to predict 12-month survival in Glioblastoma (GBM) patients using preoperative T1c and FLAIR MRIs."

1

Phase 1: Protocol & Literature Synthesis

Agent: LiteratureAgent & ProtocolAgent

Status: Completed
Task Description

Scan recent literature for GBM survival prediction markers. Draft a strict JSON protocol defining inclusion/exclusion criteria based on past failures.

Injected Context (AOT)

From Neo4j Graph: "Project 45 (2023) failed to generalize because it included post-operative MRIs. Restrict to pre-op only."

Output Result:

Protocol v1 JSON generated. Requirement locked: "Pre-operative T1c and FLAIR only. ICD-10: C71.9".

2

Phase 2: Cohort Discovery & De-Identification

Agent: CohortAgent & DeIdAgent

Status: Completed
Task Description

Translate Protocol v1 into SQL/FHIR queries to search the hospital PACS/EMR. Extract patient manifests and anonymize DICOM pixels.

Injected Context (AOT)

From Phase 1: {"inclusion": {"icd10": "C71.9", "modalities": ["T1c", "FLAIR"], "surgery_status": "pre_op"}}

Output Result:

142 valid patients found. De-identified DICOM bundle pushed to secure S3 bucket.

3

Phase 3: Vision & Tumor Segmentation

Agent: AnnotationAgent & QAAgent

Human Intervention
Task Description

Run MONAI pre-trained Brain Tumor Auto-Seg on the S3 DICOMs. Extract Whole Tumor, Enhancing Core, and Edema masks.

Injected Context (AOT)

From Global Guidelines: "Ensure spatial co-registration of FLAIR to T1c space before inference."

Human-in-the-Loop Triggered

QAAgent flagged low confidence (DSC < 0.6) on Patient #88. Execution paused. PI logged into OHIF UI, adjusted the edema threshold manually, and approved.

Output Result:

142 valid NIfTI segmentations saved to DB.

4

Phase 4: Radiomics & Survival Modeling

Agent: RadiomicsAgent & ModelAgent

Status: Completed
Task Description

Extract 3D PyRadiomics features from masks. Train an XGBoost model to predict binary 12-month survival status.

Injected Context (AOT)

From Phase 1 Protocol: "Primary Endpoint: 12-Month Survival. Evaluation Metric: ROC-AUC > 0.75."

Output Result:

Model trained. Performance: AUC 0.82. SHAP analysis confirms Texture (GLCM) and Core Volume as top features.

3. Core Infrastructure Mechanisms

Ahead-Of-Time Context Compiler

To eliminate the token-waste and non-determinism of runtime RAG within agent loops, RROS uses an AOT Context Compiler. Before dispatching a task, it assembles a static "Context Pad" grounded in the exact state of the project.

  1. 1.
    Task Extraction: Parses the DAG node and current project state (e.g., fetching the completed Phase 1 JSON).
  2. 2.
    Federated Retrieval: Queries GraphDB (Neo4j) for hard past relationships and VectorDB for semantic guidelines.
  3. 3.
    Phase-Aware Filtering: Prunes irrelevant context. Phase 4 Model Agents need the Statistical Plan, not the PICO search strings.

Event-Driven Message Bus

The Orchestrator publishes strict JSON payloads to Kafka/RabbitMQ topics. Agents run as independent, stateless consumers, ensuring absolute decoupling and horizontal scalability.

cmd.{phase}.{agent_name}

Command Topics: Used by the Orchestrator to issue tasks to specific agent enclaves.

evt.{phase}.{agent}.completed

Event Topics: Agents publish their final JSON outputs here to unblock the next DAG node.

telemetry.{project_id}

Telemetry Topics: Fire-and-forget streams. Agents emit % progress, warnings, and UI alerts here.

4. Agent Mesh Strategy & Contracts

Single Responsibility

Agents do exactly one thing well. We don't have a generic "DataAgent"; we have a CohortAgent (SQL/FHIR) and a distinct DeIdAgent (PHI scrubbing).

Contract-Driven

Agents are defined entirely by JSON Schema Inputs/Outputs. If an agent satisfies the I/O contract of a DAG node, the Orchestrator can seamlessly use it.

Planner-Critic Loops

Critical agents implement internal self-correction. They propose steps, execute external tools, and a "Critic" validates intermediate results against the Context Pad.

Example: Command Topic JSON Payload 

{
  "task_id": "uuid-v4",
  "project_id": "proj-123",
  "phase": "cohort_build",
  "task_type": "cohort_query",
  "context_augmentation": {
    "prior_learnings": [
      "proj-88 (failed): Exclude patients with metal implants to reduce MRI artifacts."
    ],
    "protocol_guidelines": "Require strict matching of Pre-op T1c."
  },
  "payload": {
    "inclusion": {"modality": ["T1c"], "icd_codes": ["C71.9"]},
    "max_patients": 500
  }
}

Memory Architecture

  • Short-term (Intra-task): Redis + ephemeral LLM context logs (retained only for the duration of the task).
  • Phase Memory (State): PostgreSQL JSONB columns track output contracts and DAG progression.
  • Cross-project (Long-term): Neo4j Knowledge Graph connects past projects, modalities, and outcomes for AOT retrieval.

Security & Deployment

  • PHI Handling: Dedicated Air-gapped DeIdAgent runs pixel-level scrubbing before data hits the S3 buckets.
  • Compute: Kubernetes cluster utilizing taint/tolerations to route heavy ModelAgent tasks to GPU nodepools.
  • Experiment Tracking: Native integration with MLflow for tracking AUC, Hyperparameters, and SHAP values.
